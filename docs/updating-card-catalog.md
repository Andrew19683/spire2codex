# Обновление каталога карт

Эта инструкция описывает обновление списка карт Spire2Codex после выхода новой версии Slay the Spire 2.

Каталог сначала извлекается из установленной игры в локальный JSON-файл, затем сравнивается с Supabase и только после ручной проверки применяется. Карты, исчезнувшие из новой версии игры, не удаляются: импортёр помечает их как `inactive`.

## Что должно быть настроено заранее

- Slay the Spire 2 установлена через Steam на этом Mac.
- В проекте установлен Node.js и выполнен `npm install`.
- Установлен .NET 9 SDK. Проверить можно командой `dotnet --version`; версия должна начинаться с `9.`.
- В `.env.local` заданы `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`.
- Есть доступ к секретному service-role key проекта Supabase. Он нужен только в момент применения импорта.
- Миграция каталога уже применена командой `npm run supabase:push`. При обычном обновлении карт повторять её не требуется, если в репозитории нет новых миграций.

## Обновление после нового патча игры

Все команды ниже выполняются из корня проекта.

### 1. Обновить игру

Установить обновление Slay the Spire 2 в Steam. Желательно один раз запустить игру без экспортёра и убедиться, что новая версия нормально открывается.

### 2. Переустановить экспортёр

После каждого обновления игры пересобрать и установить информационный мод:

```bash
npm run content:runtime:install
```

Это важно, потому что экспортёр собирается против файлов установленной версии игры.

Если игра снова попросит разрешить моды, разрешить их. В **Settings → Mod Settings** проверить, что включён **Spire2Codex Catalog Exporter**, затем перезапустить игру. Дождаться главного меню: экспортёр запишет актуальные runtime-данные во временный файл macOS.

После этого игру можно закрыть. Если есть сомнения, проверить время изменения файла: оно должно соответствовать только что выполненному запуску игры.

```bash
ls -l "${TMPDIR}spire2codex-runtime-cards.json"
```

Это защищает от случайного использования runtime-файла, оставшегося от предыдущей версии игры.

### 3. Извлечь новый каталог

```bash
npm run content:extract -- \
  --output /tmp/spire2codex-catalog.json
```

В результате должны быть:

- `locales`: только `en` и `ru`;
- `complete`: `true`;
- ненулевое количество `cards`;
- новая версия игры в snapshot.

Если `complete` равен `false`, не переходить к импорту. Нужно снова запустить игру с включённым экспортёром, дождаться главного меню и повторить извлечение.

### 4. Проверить структуру snapshot

```bash
npm run content:import -- --validate-only
```

Команда ничего не записывает в Supabase. Она проверяет ID, типы, редкости, пулы, multiplayer-признаки и наличие английского и русского переводов.

### 5. Посмотреть изменения относительно Supabase

```bash
npm run content:import
```

Это dry-run: он только читает текущий каталог и показывает будущие изменения.

Перед применением проверить:

- `catalogVersion` соответствует установленной версии игры;
- `incoming` и `active` выглядят правдоподобно;
- `added`, `changed` и `translationsChanged` соответствуют масштабу патча;
- список `deactivated` не содержит неожиданных карт;
- `coopOnly` и `soloOnly` не изменились подозрительно сильно.

Если внезапно исчезло много карт, ничего не применять. Сначала проверить версию игры, включение экспортёра и результат предыдущих шагов.

### 6. Применить импорт

Service-role key нельзя добавлять в Git, клиентский код или переменные `NEXT_PUBLIC_*`. Безопаснее временно передать его через переменную текущей terminal-сессии:

```bash
read -s "SUPABASE_SERVICE_ROLE_KEY?Supabase service-role key: "
export SUPABASE_SERVICE_ROLE_KEY
npm run content:import -- --apply
unset SUPABASE_SERVICE_ROLE_KEY
```

Импорт выполняется одной транзакцией:

- новые карты добавляются;
- изменённые карты и переводы обновляются;
- принадлежность пулам синхронизируется;
- отсутствующие в новом полном snapshot карты получают `active = false`;
- `card_challenge_settings` не изменяется;
- результат записывается в журнал `game_content_imports`.

Защита импортёра остановит операцию, если количество активных карт сокращается более чем на 30%. Не использовать `--force`, пока не подтверждено, что такое сокращение действительно произошло в игре. Для осознанного подтверждённого случая команда выглядит так:

```bash
read -s "SUPABASE_SERVICE_ROLE_KEY?Supabase service-role key: "
export SUPABASE_SERVICE_ROLE_KEY
npm run content:import -- --apply --force
unset SUPABASE_SERVICE_ROLE_KEY
```

### 7. Убедиться, что всё применилось

Повторно выполнить dry-run:

```bash
npm run content:import
```

Успешное обновление должно показать:

```text
added: 0
changed: 0
translationsChanged: 0
membershipsChanged: 0
deactivated: 0
```

После проверки удалить ключ из окружения, если он ещё задан:

```bash
unset SUPABASE_SERVICE_ROLE_KEY
```

## Если новая версия игры добавила неизвестные значения

Не обходить ошибку валидации вручную. Новый тип карты, редкость, пул или multiplayer-ограничение сначала нужно добавить в схему Supabase и парсер отдельным изменением проекта. Затем применить новую миграцию, заново извлечь snapshot и повторить dry-run.

## Короткий чек-лист

```text
1. Обновить и проверить запуск игры.
2. npm run content:runtime:install
3. Включить exporter, перезапустить игру и дождаться главного меню.
4. npm run content:extract -- --output /tmp/spire2codex-catalog.json
5. npm run content:import -- --validate-only
6. npm run content:import
7. Проверить diff.
8. npm run content:import -- --apply с временно заданным service-role key.
9. Снова npm run content:import и убедиться, что diff пустой.
```
