# Spire2Codex — Slay the Spire 2 Challenge Portal

Полноценный MVP портала челленджей. Интерфейс — русский, имена игрового контента — английские. В текущей версии данные и demo-сессия сохраняются в `localStorage`, поэтому внешняя база не нужна: проект можно проверить сразу и бесплатно разместить на Vercel.

> `localStorage` — только временный MVP-слой. Он подходит для локальной проверки, но не для настоящих аккаунтов, просмотра статистики других игроков или совместных челленджей. Предметная логика и интерфейс не обращаются к нему напрямую: чтение и запись скрыты за repository-интерфейсом.

## Что реализовано

- вход по email/паролю и быстрый demo-вход; выход из аккаунта;
- главная страница с плиткой Ladder Challenge;
- раздельные настройки языка интерфейса и игрового контента (структура готова к добавлению переводов; MVP отображает RU/EN по умолчанию);
- выбор одного из 5 персонажей и случайный выбор; список централизован и расширяется до 10 без изменения логики;
- один активный забег, шкала A1–A10, фиксация победы и поражения;
- статистика по персонажам и общая строка, корректная средняя высота;
- сортировка: прохождения ↓, средняя высота ↓, порядок персонажей в игре;
- история от новых к старым, пагинация 5/10/20;
- контрастное оформление успешного челленджа;
- неброское удаление записи с подтверждением;
- адаптивный интерфейс для телефона.

## Локальный запуск

Нужен Node.js 20.9 или новее.

```bash
npm install
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000). Нажмите «Продолжить в demo-режиме» либо заполните любую корректную почту и пароль длиной от 4 символов.

## Как проверить сценарий

1. Войдите и откройте плитку Ladder Challenge.
2. Выберите персонажа вручную или случайно и начните восхождение.
3. Отмечайте победы — после A10 забег попадёт в историю как пройденный.
4. В новом забеге нажмите «Поражение» — история покажет вознесение, на котором он завершился.
5. Проверьте статистику, переключение размера страницы и подтверждение удаления.
6. Обновите страницу: состояние сохранится в браузере. Кнопка «Выйти» завершает demo-сессию, но не удаляет данные.

## Архитектура

- `src/domain` — чистая предметная логика и типы, не зависящие от интерфейса или хранилища.
- `src/app` — Next.js App Router и клиентский интерфейс.
- `src/storage` — контракт `UserDataRepository` и временная реализация `LocalStorageUserDataRepository`.
- состояние хранится одним объектом `UserData`; UI работает с repository-контрактом, а не с API браузера.

При переименовании проекта старые локальные данные автоматически переносятся из ключа `spirebound.demo.v1` в `spire2codex.demo.v1`.

## Рекомендуемая миграция на PostgreSQL / Supabase

1. Подключить Supabase Auth и заменить demo-флаг на реальную пользовательскую сессию.
2. Создать таблицу `runs` с полями `id`, `user_id`, `character_id`, `status`, `current_ascension`, `completed_ascensions`, `started_at`, `finished_at`.
3. Создать таблицу `profiles` для языковых настроек и будущих публичных данных игрока.
4. Включить Row Level Security: пользователь изменяет только свои записи; публичную статистику отдавать отдельной безопасной политикой или представлением.
5. Реализовать `SupabaseUserDataRepository` с тем же контрактом `load`/`save` (при переходе к серверу методы можно сделать асинхронными) и внедрить его вместо localStorage-адаптера.
6. Для кооперативных челленджей добавить таблицы `challenges`, `challenge_members` и связь забега с челленджем.

Расчёт Ladder и статистики останется в `src/domain`; при миграции не потребуется переписывать его или компоненты отображения.

## Бесплатный деплой

1. Загрузите репозиторий на GitHub.
2. Импортируйте его в Vercel.
3. Framework Preset определится как Next.js; переменные окружения не нужны.
4. Нажмите Deploy.

Важно: demo-режим предназначен для MVP — данные привязаны к браузеру, а не к реальному аккаунту. Перед доступом с разных устройств нужно подключить Supabase.
